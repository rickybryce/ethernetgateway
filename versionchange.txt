# versionchange.txt
#
# Checklist of files that carry the project version string and must be bumped
# on every version change. Tracked in-repo as a maintenance aid.
#
# Runtime version strings (ATI / ATI3, Kermit identity, webserver banner, GUI
# title, startup log) all derive from env!("CARGO_PKG_VERSION"), so bumping
# Cargo.toml updates them automatically — the doc files below must be matched
# by hand.
#
# Current version: 0.8.1
#
# ── Source of truth ─────────────────────────────────────────────
Cargo.toml              # package version (line 3 only — NOT the russh/dep "0.60" specs); Cargo.lock follows on build
versionchange.txt       # the "Current version:" line in this file's header
#
# ── Documentation (match Cargo.toml by hand) ────────────────────
README.md               # (no version string since the v0.7.0 trim — verify with the grep below)
THIRD-PARTY-NOTICES.md  # only OUR OWN "[ethernetgateway X.Y.Z]" line; every other
#                         X.Y.Z there belongs to a third-party crate.  Regenerated
#                         wholesale by cargo-about at release time.
usermanual.html         # .version header, sha256 example, Kermit identity, ATI/ATI3 strings, footer
#                         DO NOT bump the historical refs: "removed in v0.6.0", "prior to v0.6.0"
usermanual.pdf          # regenerate from the updated HTML — same tool as before:

# ── On release (separate step) ──────────────────────────────────
CHANGELOG.md            # Pre-release, the next version's notes accumulate under a
#                         "## [X.Y.Z] - Unreleased" heading. At release time:
#                           1. Change "- Unreleased" to the release date: "## [X.Y.Z] - YYYY-MM-DD"
#                           2. Repoint the link ref from compare/...HEAD to the tag:
#                              [X.Y.Z]: https://github.com/rickybryce/ethernetgateway/releases/tag/vX.Y.Z
#                           3. Keep the [Unreleased] line for the next cycle's work
#                         Then tag vX.Y.Z and merge dev -> master to trigger the Release workflow.
#
# Verify after a bump:
#   grep -rn '<OLD VERSION>' web/ README.md usermanual.html   # expect: none
#   grep -n  '0\.6\.0' usermanual.html  # expect: ONLY the two historical refs
#   cargo build                          # confirms Cargo.toml parsed + new version
#                                        # compiled, and updates Cargo.lock
#
# ── BEFORE TAGGING: check CI, not just the local suite ─────────
#   gh run list --workflow=ci.yml --limit 5
#     Every recent master run must be `success`.  A local `cargo test` is NOT a
#     substitute: CI runs the suite on ubuntu, macOS AND Windows, and a
#     platform-specific failure is invisible here.  0.8.0 was tagged with the
#     Windows job red for three pushes because only the local suite and the
#     *release* workflow were checked — release.yml builds and signs, it never
#     runs the tests, so it is green regardless.
#   gh run view <id> --log-failed        # if red, before doing anything else
#
# ── AFTER TAGGING: watch the release pipeline ──────────────────
#   gh run list --workflow=release.yml --limit 3
#   until [ "$(gh run view <id> --json status -q .status)" = completed ]; \
#       do sleep 30; done; gh run view <id> --json conclusion -q .conclusion
#   gh release view vX.Y.Z --json assets -q '.assets | length'   # expect 24
#   Then spot-check one artifact: download it with `gh release download`,
#   `sha256sum -c` its .sha256, and run the extracted binary to confirm it
#   prints the new version.
