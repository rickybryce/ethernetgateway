Overview

The gateway can serve its transfer directory over FTP, to any FTP client — a modern PC, a DOS machine with a packet driver, or a vintage computer with a TCP/IP stack.

The server is written for the gateway rather than taken from a library (the leading Rust FTP library has no protection against the FTP “bounce” attack and can’t be extended), and it uses the gateway’s own security: the same login, lockout and private-address rules as telnet. It lives in src/ftp/: proto.rs (the protocol pieces), session.rs (one control connection), store.rs (every file operation, behind the jail) and remote.rs (a slave’s operations, carried to its master).

Files are sent exactly as stored. The transfer directory is a byte-exact store for vintage machines: a CP/M text file needs its CR LF line endings and a Commodore file its bare CRs. So ASCII mode (TYPE A) is accepted but translates nothing — clients such as Windows ftp that start in ASCII mode transfer binaries intact. The same choice vsftpd ships with.
Enabling the Server

Off by default, on port 2121; set from any of the three configuration screens.

WhereHow
Desktop windowServer → More…: the FTP Server checkbox, its Port, and Passive.
Web pageServer → More…: the same three fields, under FTP Server.
TelnetConfiguration → Server Configuration: X turns FTP on or off; Y sets the port, then the passive range.
egateway.confftp_enabled, ftp_port, ftp_passive_ports (see Config).

Turning the server on or off, or changing its port, takes effect on restart, like every listener. The passive range is read on every passive connection, so it applies at once. A port that clashes with the telnet, SSH, web or Kermit listener is refused, and so is a passive range that takes in any listener’s port.

Logging In & Security

FTP follows Require Login, exactly as telnet does.

SettingWho may connectLogin
Require Login offPrivate addresses only (RFC 1918, loopback, link-local, ULA) — unless IP Safety is disabled. Block gateway connections refuses this network’s router.Anonymous: any username, any password.
Require Login onAny address (the login is the gate).The gateway’s username and password. anonymous / ftp are refused at once, and that refusal is not counted against you — browsers and clients try it on their own.
  • One lockout for every surface. Three wrong passwords lock the address out of telnet, SSH, the web page and FTP for five minutes. An FTP client with a saved wrong password that retries on its own can therefore lock that PC out of the web page too.
  • One connection budget. The per-IP connection rate (conn_rate_max / conn_rate_window_secs) counts FTP control connections together with telnet and SSH; over the limit, a connection is dropped silently. FTP sessions are capped at max_sessions, counted separately from telnet’s and SSH’s.
  • No user enumeration. Every USER except the refused anonymous names gets 331, and a wrong username or password gets the same 530 in the same time. There is a one-second pause after each failed login, as on telnet.
  • Passwords are never logged, not even with verbose logging on (the line reads PASS ****).
  • Clear text. FTP sends the password unencrypted, as telnet does. There is no FTPS: AUTH answers 502, so modern clients fall back to plain FTP. Keep FTP on a trusted network.
What FTP Does With Files

Everything happens inside the transfer directory, under the same rules as the gateway’s other ways of moving files.

RuleDetail
The jail/ is transfer_dir. .. never climbs above it, and every existing file is checked by its real path, so a symlink can’t lead out.
New namesA file or folder FTP creates must use letters, digits, ., - and _, up to 64 characters — the rule every other upload follows, so the name still works in the Gateway Shell and on CP/M and Commodore machines. Anything else is refused with 553 and the reason; the name is never quietly changed. Existing files with other names (spaces included) can still be listed, downloaded, renamed and deleted.
UploadsSTOR writes beside the target and renames over it when complete, so a broken upload never leaves half a file under the real name. (A crash or power cut can leave that hidden .egw-ftp- file behind; listings never show it, and it can be deleted on the gateway machine.) APPE and a resumed upload (REST + STOR) write in place. An upload is refused (452) when the disk is over 90% full.
One writer per fileWhile one session uploads a file, another session’s upload, delete or rename of it is told the file is busy (450).
Disks in useA disk image mounted on a CP/M drive or running in a booted machine, or a file a CP/M program is writing, can be downloaded but not replaced, appended to, renamed or deleted (550 In use by the CP/M emulator.). The emulator’s own CPM folder and the folders in it can’t be renamed or removed.
RenameA file may replace a file, as clients expect; nothing replaces a folder, and a folder can’t be moved inside itself.
Data Connections & Firewalls

FTP opens a second connection for every listing and every file.

ModeCommandsHow it is protected
Passive (most clients)PASV, EPSVThe gateway opens a port and accepts one connection, from the control connection’s own address only, within 30 s. Anyone else connecting to it is dropped (RFC 2577 “port theft”).
Active (Windows ftp, DOS clients)PORT, EPRTThe gateway connects back only to the client’s own address, on port 1024 or above. Any other target is refused — the FTP “bounce” attack (RFC 2577).
Behind a firewall or router: set ftp_passive_ports (e.g. 50000-50100, or a single port) and open that range as well as the FTP port. Without it the operating system picks a random port that no firewall rule can anticipate. The passive reply names the address the client reached the gateway on; behind NAT that is a private address, which curl and FileZilla already replace with the address they connected to.

IPv4 only, as every gateway listener is today: EPRT for IPv6 answers 522. A data connection that moves nothing for 120 s is given up.

FTP on a Slave

On a slave, every file you see and every change you make is on the master’s transfer directory.

The slave runs the FTP protocol for its own clients — its login, address rules and data connections are all its own — and carries each file operation to the master over the SSH link it already has. The master carries it out with the same jail and the same CP/M checks it applies to its own FTP clients, and re-checks every path the slave sends.

  • One connection, a channel per session. The slave opens one SSH connection for FTP (on the first login) and gives each FTP session its own channel on it; the connection closes a minute after the last session ends. A new connection per login would trip the master’s per-IP connection rate, which the slave’s serial relays share.
  • Downloads are paced. The master sends a few blocks ahead and waits for the slave to take them, so one slow client can’t hold up the other FTP sessions sharing the connection.
  • Uploads are confirmed. The slave reports a file saved only once the master has written it to disk.
  • No fallback. If the master can’t be reached, the login is refused (421) with the reason; a slave never serves its own transfer directory over FTP.
  • What the master needs. SSH on, accept relays on, and this slave’s login (its enrolled key, or the master password). No separate FTP switch on the master. Master and slave must run the same version.
