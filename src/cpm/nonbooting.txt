DISKS THAT DO NOT BOOT
======================

Disks that carry something a cold start accepts as a boot program, and then
never reach a sign-on.  The three boot pickers withhold these, because a list
of disks that will not start is worse than a short list: an operator has no
way to tell a disk that cannot work from one they have configured wrongly,
and every one they try costs them a session.

This file is MEASURED, not reasoned.  It is generated by the `#[ignore]`
`record_nonbooting` test, which boots every image in every collection through
the product's own path and writes down the ones that never speak -- console
or VDM-1 card, since a disk that paints its sign-on into screen memory has
booted perfectly well.

Identity is the **SHA-256 of the image**, never the filename.  Eight names in
these collections exist in more than one of them and are different disks, and
an operator may rename anything; a hash cannot be wrong about which file this
is.  The size is carried with it so the common case costs one `stat` and no
hash at all.

**A disk that is not in this file is offered.**  That is the whole safety
rule: this list can only ever withhold something somebody has actually booted
and watched fail, so a disk nobody here has seen -- one an operator built
themselves -- keeps the old, generous treatment and still appears.  Erring the
other way would refuse a disk that works, which is a fault the operator cannot
work around.
